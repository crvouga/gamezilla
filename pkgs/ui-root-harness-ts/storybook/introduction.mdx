# Design system

This Storybook renders the production Solid components with the app's fonts,
tokens, themes and localization. No app server, account or database is required.
Find components through the sidebar or search, then open Docs for their prop contracts.

## Develop a component

Start with [Button](?path=/story/components-inputs-button--interactive).
Change its title, size, intent or loading state in Controls. Use the Viewports
toolbar for Phone, Tablet and Desktop, and the theme toolbar for Light and Dark.
The Interactions panel shows each story's executable play steps.

[TextInput](?path=/story/components-inputs-textinput--controlled) synchronizes
typing with the value in Controls. [Banner](?path=/story/components-feedback-dismissiblebanner--interactive)
exposes position, tone and visibility there, without extra configuration widgets
in the canvas. Use Controls' reset to restore story defaults; callback spies
appear in Actions. Separate interaction stories demonstrate scripted flows.

Stories import real production components. Add or change a component's
`*.stories.tsx` beside its implementation in `pkgs/*-client-ts/src/`.
Use its public prop contract and existing design tokens; screens compose the
design system. Include empty, loading, success and recoverable failure states
where they apply. Add source JSDoc for the generated Docs page.

The sidebar follows atomic design: Foundations, Atoms, Molecules, Organisms,
and Templates. Games has one folder per game, such as Chess and Connect Four.
Games / Shared / Screens holds screens and layouts reused across games;
Games / Shared / Components holds reusable game regions. Source stories stay
beside their production components. Existing story URLs stay stable.

## Inspect with Essentials

Use Actions for callback payloads, Controls for component args, and the theme
toolbar for production Light/Dark. Backgrounds offers token-based Canvas,
Surface and Muted surface backdrops; its grid follows the 4px spacing grid.
Changing the backdrop keeps the component's theme and state.

Use Measure (toolbar or `m`) to inspect box dimensions and spacing, and Outline
to locate layout boundaries without editing component CSS. The accessibility
addon uses native Highlight to locate affected nodes; targeted debugging can
use Storybook's public Highlight channel API. Turn inspection overlays and grids
off before authoring visual baselines.

Viewport offers Phone, Tablet and Desktop, rotation for landscape, and reset
for the unconstrained canvas. Story globals may lock a setting for a specific
state; ordinary stories keep the toolbars available for exploration. The full
Essentials audit and task guidance live in the harness README under
**Essentials review and usage**. Native inspection helps design and debugging;
it does not replace automated verification.

## Run and share

| Command | Result |
| --- | --- |
| `bun dev` | App stack and Storybook together; Storybook listens on port 6006. |
| `bun storybook` | Storybook alone, through the same boot owner. Stop an app boot with `bun kill` first. |
| `bun kill` | Stops the checkout's owned servers. |
| `bun storybook:build` | Static site in `pkgs/ui-root-harness-ts/.cache/storybook/`. |

Share the built directory through your team's approved static host, then copy a
component's story URL for feedback. The bundle needs no backend. Building does
not publish it or create a public URL.

## Verify a change

The project uses Bun for component contracts and Playwright for Storybook browser
checks. The built-in Interactions panel runs play functions; no Vitest or hosted
visual testing account is needed.

| Command | Verification |
| --- | --- |
| `bunx turbo run @pkgs/ui-root-harness-ts#tc @pkgs/ui-root-harness-ts#test` | Types, component contracts and story inventory. |
| `bun storybook:coverage` | Component, source documentation, story and baseline coverage. Reports are in the harness's `.cache/storybook-coverage.json` and `.md`. |
| `bun storybook:test` | Story rendering, play functions, serious/critical axe accessibility violations and visual comparisons in both themes, plus the Storybook integration checks. |
| `bun verify` | Full release gate, including a representative Storybook browser suite. |

Visual comparisons never update baselines implicitly. To intentionally regenerate
them, use `bun storybook:test --update-snapshots`, then run comparisons without
the update flag. Full theme and responsive coverage also runs in the nightly
visual group. Test failures block their gate; opening a story is for development,
not verification evidence.

## Time and agent discovery

Each story mount gets a fresh virtual clock. Use the time toolbar to advance it;
return to Paused between repeated equal steps. Interactions can dispatch
`advance-story-time` on `#storybook-root` with milliseconds in the event detail.
Do not introduce wall timers into component demos.

Agents can discover running story previews at the printed Storybook origin plus `/mcp`.
For another computer, use the printed LAN URL or forward the printed port; its
`localhost` refers to the viewing computer. The T3 **Run Storybook on LAN** action
enables LAN access; **Run Storybook (local or tunnel)** keeps loopback binding.
The static build's `/index.json` and `/manifests/components.json` provide canonical
story IDs and component contracts; `/manifests/docs.json` indexes this guide.
The component manifest embeds prop descriptions and focused usage examples;
the docs manifest embeds the full guide and its summary.
Stories explain when and why to use a component. Comparison galleries stay in
the sidebar but are omitted from agent manifests when focused examples cover
the same component. Their rendering and automated verification remain intact.
The repository workflow and implementation
details live in `pkgs/ui-root-harness-ts/README.md` under Agent workflow.
Use `/storybook-ui <task>` in a supported agent harness to load that workflow
for building, reviewing or maintaining UI.
